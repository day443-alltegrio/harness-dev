# Harness review 2026-10-23 (baseline)

- Kit version reviewed: 0.1.0 (first version)
- Previous review: none
- Evidence: `research/harness-engineering.md` (22.10.2026) and its primary sources,
  the fact check in `research/sources/`, the pilot in `research/case-study-pilot.md`.
  No new web search in this baseline; the next review starts from this date.

## Verdict

The field has settled on one idea: the gains come from the environment around the
agent, and most of all from deterministic checks and enforced verification, while
checking behaviour and task understanding remains unsolved and stays with people. A
generic harness should therefore ship strong defaults for boundaries, verification and
feedback, keep its own context small, measure itself, and be versioned so it can be
upgraded and pruned as models improve. Version 0.1.0 covers the first three levels of
that well; its gaps are in measuring the harness itself (false blocks, evals), in the
strongest boundary (the OS sandbox) and in regression replay.

## What a generic harness should contain

| Need | Why (evidence) | Kit 0.1.0 |
|---|---|---|
| Boundaries: deny destructive and secret actions, ask before irreversible and outbound ones | lethal trifecta (Willison); approvals for irreversible actions are common to every primary source | guard hook, deny rules, per-action approvals in rules |
| Enforced verification before "done" | LangChain's pre-exit verification hook; agents misjudge their own work (Anthropic) | Stop hook with fast checks; gate report in every work reply |
| Deterministic gates outside the agent | OpenAI and Thoughtworks: invariants enforced mechanically, cheap checks first | preflight, deploy check, harness tests |
| Every rule tied to a failure, feedback into rules | Osmani's ratchet; Böckeler's steering loop | failure catalog, project incidents, coverage registry, skill `harness-incident` |
| Context as a map with a budget | OpenAI's 100-line AGENTS.md; ETH Zurich: excess context costs success and money | `CLAUDE.md` template as a map, imported rules, budgets check |
| Contracts before big work | Anthropic's sprint contract between planner and evaluator | contract template and check |
| A skeptical reviewer separate from the author | Anthropic's planner, generator, evaluator | `harness-change-reviewer`, `harness-docs-reviewer` |
| Entropy control | OpenAI's garbage collection; harness ages with the model (Anthropic) | monthly cleanup skill, thresholds, drift warning |
| Measurement of the harness itself | open problem in every source: is a silent sensor good or blind? | gate table, telemetry, coverage only with firing tests; no false-block marking yet |
| Versioned templates with an upgrade path | Böckeler: harness templates will hit the versioning problems of service templates | SemVer, changelog, lock with hashes, safe upgrade, migrations |

## Radar

Rings: adopt (default in the kit), trial (in the kit, still proving itself), assess
(watch, prototype), hold (do not copy now).

| Practice | Ring | Note |
|---|---|---|
| Deterministic gates outside the agent, cheap first | adopt | in the kit |
| Guard hook for destructive git, secrets, deploy, outbound | adopt | in the kit; second line behind server rights |
| Verification hook before the agent stops | adopt | Stop hook, bounded blocks |
| Failure becomes a check with a firing test | adopt | registry is honest by test |
| Context as a map, budgeted | adopt | budgets check |
| Per-action human approval for irreversible steps | adopt | rules and guard |
| Supply chain: pins, lock files, plugin and MCP allowlist | adopt | in the kit |
| Empty or stale evidence is a failure | adopt | gate table, scanners |
| Versioned harness with safe upgrades | adopt | harness.py |
| Skeptical reviewer subagent | trial | read-only by description, not by rights |
| Scenario-to-code map with fingerprints | trial | strong in the pilot; heavier to adopt |
| API contract diff before the swap | trial | for services with OpenAPI |
| Agent telemetry from transcripts | trial | numbers only |
| OS sandbox with a network allowlist | assess | the strongest boundary; needs a list of every network need |
| ConfigChange hook against switching hooks off | assess | small, next version |
| Golden tasks to measure harness changes | assess | answers "did the rule help or only tighten" |
| Marking false blocks in the hook log | assess | needed for the 20% threshold to be real |
| Structural and LSP sensors, mutation tests on core primitives | assess | per stack |
| Ephemeral environment per worktree | assess | per stack, heavy |

| Minimal merge gates of large teams | hold | irresponsible at low volume, by their own authors |
| Full autonomy without people | hold | behaviour checks have no reliable sensor |
| Vendor statistics as arguments | hold | directional only |

## Gaps, ranked (roadmap)

1. **Measure the harness**: false-block marking in the hook log and a ConfigChange hook
   (0.2).
2. **Stack presets for Stop checks and preflight**: ruff F, tsc, go vet, with timeouts
   (0.2).
3. **Sandbox template**: Claude Code sandbox settings with a network allowlist, and a
   guide to list the network needs (0.3).
4. **Regression replay** of closed tickets with confirmed results as a generic
   mechanism (0.3).
5. **Schema snapshot** in the deploy check: columns and grants the code expects (0.3).
6. **Golden tasks** for harness changes (0.4).
7. **AGENTS.md export** of the generic rules (0.4).
