# Incidents of this project

Project-owned. Every failure the harness should have caught goes here, with a date,
once: it is either an example of a generic pattern from
`harness/core/docs/failure-patterns.md` (A1..A10, B1..B11) or a new project pattern
(P1, P2...). The check that now catches it and its test go to
`harness/config/incident-coverage.json` (skill `harness-incident`). No personal data,
internal IDs or secrets here: describe the failure, not the record.

## Project patterns

Patterns that the generic catalog does not have. The title must match the registry
